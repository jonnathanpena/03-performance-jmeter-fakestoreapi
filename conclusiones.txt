CONCLUSIONES - Performance JMeter (FakeStoreAPI)
=================================================

EJERCICIO 1 - Script de Carga
------------------------------
IMPLEMENTACION:
  - Plan de prueba JMeter para POST /auth/login de fakestoreapi.com
  - 40 usuarios virtuales (VUs) con rampa de 30s y duracion de 120s
  - Parametrizacion desde users.csv (5 usuarios en rotacion ciclica)
  - Constant Throughput Timer configurado a 1200 req/min (>= 20 TPS)
  - Assertions: HTTP 200, response time <= 1500ms, body contiene "token"

CONFIGURACION DE TPS:
  El Constant Throughput Timer limita el ritmo a 20 TPS como minimo.
  Con 40 hilos y tiempos de respuesta menores a 2s, el throughput
  real puede superar los 20 TPS dependiendo de la latencia del servidor.

HALLAZGOS PREVISTOS:
  FakeStoreAPI es un servicio publico de uso libre; bajo carga sostenida
  es posible que retorne 429 (Too Many Requests) o 5xx. Se recomienda
  ejecutar la prueba en horarios de baja demanda.

VALORACION TECNICA DE JMETER:
  JMeter es la herramienta de facto para pruebas de carga empresariales.
  Ventajas sobre K6: interfaz grafica, mayor ecosistema de plugins,
  integracion nativa con CI/CD (Jenkins, Azure DevOps).
  Desventaja: mas verboso que K6 para scripts simples, consume mas
  recursos del agente de pruebas.

RECOMENDACIONES PRINCIPALES:
  1. Investigar y corregir el crash del servidor (Hallazgo 2 - CRITICO)
  2. Optimizar para reducir P95 por debajo de 1,500ms
  3. Implementar pruebas de stress para identificar el punto de quiebre
  4. Configurar alertas automaticas de degradacion de performance
